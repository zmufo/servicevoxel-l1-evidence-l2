## 层 B：运行输出一致性检查

第 5 项原始 stdout 缺失，层 B 当前状态必须为：

layer_B: NOT_COVERED
reason: original_stdout_missing

不得用层 A 的 PASS 推定层 B 通过；不得把"文档内表格前后一致"写成"与原始运行输出一致"。

## 禁止事项

- 不得重跑脚本生成新输出冒充原始输出。
- 不得为消灭 null 代填阈值。
- 不得宣称双盲（口径为独立首轮标注 + 来源尽量盲化 + 争议由 adjudicator 仲裁，提交前互不可见）。
- 不得以自写规则冒充第三方基线。
- 不得将文档内部一致性写成"与原始运行输出一致"。

## 回执提交指引

复核完成后，请按以下流程提交回执：

1. Fork 本仓库到你的 GitHub 账号（不要直接推送主分支）。
2. 新建分支：命名为 review/你的姓名或机构简称（如 review/zhang-san）。
3. 填写回执：将 review_receipt_v1.0.yaml 模板复制到同目录下，文件名改为 REVIEW_RETURN_你的姓名.yaml，按实际判定结果填写字段。
4. 提交到你的 Fork，然后向本仓库 main 分支发起 Pull Request。
5. PR 描述中注明：复核人身份、是否参与修订（须为 NOT_PARTICIPATED_IN_REVISION）、层 A 结论摘要。
6. 发布方审核 PR 后合并；合并即代表回执正式登记，不由发布方代填任何判定值。

注意：回执模板中所有 PENDING / null 字段均由复核人本人填写，发布方仅负责审核合并，不预设结论。
